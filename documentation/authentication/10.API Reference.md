## Authentication API Endpoints

### Base URL

```
Development: http://localhost:3000
Production: https://your-domain.com
```

### API Prefix

All server endpoints are mounted under `/api` (see `server/src/app.js`).

Examples:

- `/api/users/...`
- `/api/jobs/...`
- `/api/travel/...`

### Client `useFetch` convention (important)

On the client, the `useFetch(route, ...)` hook automatically prefixes requests with `/api`.

- Pass routes like `"/users/login"` or `"/jobs/search"` (no `/api`).
- The hook will request `"/api/users/login"` or `"/api/jobs/search"` under the hood.

This API reference lists the **actual HTTP endpoints** (including `/api/...`).

### Authentication Headers

```javascript
// All requests include credentials for cookies
credentials: "include"

// Content-Type for POST/PUT requests
Content-Type: "application/json"
```

### General Notes

- **Protected Routes**: Most user-related endpoints require JWT authentication
- **Guest Access**: Job search endpoint (`POST /api/jobs/search`) accepts both authenticated and unauthenticated requests
- **Rate Limiting**: Authentication endpoints (login, signup) are rate-limited to 5 requests per 5 minutes per IP
- **Token Storage**: JWT tokens are stored in httpOnly cookies with 24-hour expiration

## 1. User Registration

### POST /api/users

Create a new user account.

**Request Body:**

```javascript
{
  "user": {
    "first_name": "John",
    "last_name": "Doe",
    "email": "john.doe@example.com",
    "password": "SecurePass123!",
    "skills": ["JavaScript", "React", "Node.js"],
    "street": "123 Main St",
    "house_number": "Apt 4B",
    "city": "New York",
    "country": "USA"
  }
}
```

**Response (201 Created):**

```javascript
{
  "success": true,
  "user": {
    "id": "uuid-v4",
    "email": "john.doe@example.com",
    "first_name": "John",
    "last_name": "Doe",
    "avatar": null,
    "street": "123 Main St",
    "house_number": "Apt 4B",
    "city": "New York",
    "country": "USA",
    "skills": ["JavaScript", "React", "Node.js"],
    "favorites": []
  },
  "token": "jwt-token"
}
```

**Error Responses:**

- `400 Bad Request`: Invalid input data, validation errors
- `500 Internal Server`: Database error

**Rate Limiting:** 5 requests per 5 minutes per IP

## Job Search API (Accessible to All Users)

### POST /api/jobs/search

Search for jobs by query string. Can be accessed by both authenticated and unauthenticated users. If authenticated, the search is cached with the user ID for optimization.

**Authentication:** Token verification middleware runs, but guest access is allowed. If authenticated, cached results may be returned on subsequent searches.

**Request Body:**

```javascript
{
  "search_string": "React Developer"
}
```

**Response (200 OK):**

```javascript
{
  "success": true,
  "result": [
    {
      "id": "job-unique-id",
      "title": "React Developer",
      "organization": "Tech Company",
      "organization_url": "https://example.com",
      "employment_type": "full-time",
      "url": "https://example.com/job/123",
      "organization_logo": "https://example.com/logo.jpg",
      "display_location": "Remote",
      "work_mode": "remote",
      "seniority": "mid",
      "description_text": "Full job description...",
      "date_posted": "2024-01-15T10:00:00Z",
      "normalized_description": "Normalized job description..."
    }
  ],
  "msg": "New vacancies will be available in our DB in 1-10 min; search for the same job title to find them." // Only present for authenticated users when search is not fully cached
}
```

**Note:** For authenticated users, if the search string is not fully cached, the response may include a `msg` field indicating that additional jobs from the LinkedIn scraper will be available in approximately 10 minutes. The endpoint triggers a background fetch process for authenticated users to enhance results.

**Error Responses:**

- `400 Bad Request`: Missing or non-empty string `search_string` in request body
- `500 Internal Server`: Search error or API failure

## Authentication Middleware

### verifyToken Middleware

Applied to all protected routes to validate JWT tokens.

**Process:**

1. Extract token from httpOnly cookie
2. Verify JWT signature and expiration
3. Check token against blacklist
4. Attach user data to request object

**Error Responses:**

- `401 Unauthorized`: No token, invalid token, expired token, blacklisted token

### Rate Limiting

Applied to authentication endpoints to prevent abuse.

**Configuration:**

- Login: 5 requests per 5 minutes per IP
- Registration: 5 requests per 5 minutes per IP

**Error Response:**

- `429 Too Many Requests`: Rate limit exceeded

## Security Considerations

### Token Storage

- JWT tokens stored in httpOnly cookies
- 24-hour expiration
- Automatic blacklisting on logout

### Password Security

- Minimum 8 characters
- Must include uppercase, lowercase, numbers, symbols
- Hashed with bcrypt (12 salt rounds)

### Rate Limiting

- Authentication endpoints limited per IP
- 5 requests per 5 minutes
- Prevents brute force attacks
- Configurable limits and time windows

### Input Validation

- All inputs validated server-side
- Type checking and sanitization
- Protection against injection attacks
- Parameterized database queries

## 13. Travel

### POST /api/travel/batch

Calculate travel times and transfers for multiple work cities from a user's home address.

**Authentication:** Optional (endpoint itself doesn't strictly require it, but client sends it via `useFetch` if available).

**Request Body:**

```javascript
{
  "homeAddress": {
    "homeStreet": "Main St",
    "homeHouseNumber": "123",
    "homeCity": "Amsterdam",
    "homeCountry": "Netherlands"
  },
  "workCities": ["Rotterdam", "Utrecht", "Amsterdam"]
}
```

**Response (200 OK):**

```javascript
{
  "success": true,
  "result": {
    "homeAddress": "Main St 123, Amsterdam, Netherlands",
    "travelDetails": [
      {
        "workCity": "Rotterdam",
        "travel_time": 45, // in minutes
        "least_transfers": 1
      },
      {
        "workCity": "Utrecht",
        "travel_time": 25,
        "least_transfers": 0
      },
      {
        "workCity": "Amsterdam",
        "travel_time": 0, // Same city logic
        "least_transfers": 0
      }
    ]
  }
}
```

**Note:** If Google Maps fails for a work city, that entry in `travelDetails` may include an `error` field instead of `travel_time` and `least_transfers`.

**Error Responses:**

- `400 Bad Request`: Missing `homeAddress` or `workCities` array in request body
- `500 Internal Server`: Error during travel calculation
