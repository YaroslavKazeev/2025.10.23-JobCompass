```mermaid
sequenceDiagram
    autonumber
    actor User
    %% File paths:
    %% SignupForm: client/src/pages/SignupForm.jsx
    %% AlertMessage: client/src/components/AlertMessage/AlertMessage.jsx
    %% UserContext: client/src/context/UserContext.jsx
    %% createUser: server/src/controllers/user.js
    participant SignupForm as SignupForm Component<br/>SignupForm.jsx
    participant AlertMessage as AlertMessage Component<br/>AlertMessage.jsx
    participant UserContext as UserContext Provider<br/>UserContext.jsx
    participant Server as Server Controller<br/>user.js

    Note over User,Server: Phase 1: User Registration
    User->>SignupForm: Fills registration form<br/>(name, email, password, etc.)
    activate SignupForm

    SignupForm->>SignupForm: Client-side validation<br/>- Email format<br/>- Password strength<br/>- Password match
    deactivate SignupForm

    alt Validation fails
        activate SignupForm
        SignupForm->>SignupForm: Set alert state with<br/>validation error<br/>(type: "error", message: error text)
        SignupForm->>AlertMessage: Render error alert
        activate AlertMessage
        AlertMessage->>User: Display validation error<br/>(e.g., "Password too weak")
        deactivate AlertMessage
        Note over SignupForm,User: Registration stops here
        deactivate SignupForm
    else Validation succeeds
        activate SignupForm
        SignupForm->>Server: POST /api/users<br/>body: { user: { first_name, last_name, email, password, ...defaultUser } }<br/>credentials: "include"
        activate Server

        Server->>Server: Validate input data<br/>with validateCreactUser()
        Server->>Server: Check if email already exists
        Server->>Server: Hash password with bcrypt<br/>(12 salt rounds)
        Server->>Server: Create user in database<br/>with UUID
        Server->>Server: Generate JWT token<br/>(sign with user id, email)
        Server->>Server: Set httpOnly cookie<br/>maxAge: 24 hours
        deactivate Server

        alt Registration fails
            activate Server
            Server->>SignupForm: Return error response<br/>(400/500 status, error message)
            SignupForm->>AlertMessage: Display error alert
            activate AlertMessage
            AlertMessage->>User: Show registration error
            deactivate AlertMessage
            deactivate Server
        else Registration succeeds
            activate Server
            Server->>SignupForm: Return success response<br/>(201 status, user data, token)
            deactivate Server

            SignupForm->>UserContext: Dispatch "REGISTER" action<br/>with user data
            activate UserContext
            UserContext->>UserContext: Update global user state
            deactivate UserContext

            SignupForm->>User: Show success popup
            Note over SignupForm,User: User is now authenticated
        end
        deactivate SignupForm
    end
```

## Key Components & Files

### Client Side

- **SignupForm.jsx** (`client/src/pages/SignupForm.jsx`)
  - Handles form input and validation
  - Password strength requirements display
  - Real-time validation feedback
  - GDPR compliance notice

- **UserContext.jsx** (`client/src/context/UserContext.jsx`)
  - Global authentication state management
  - User data persistence across app

- **AlertMessage Component** (`client/src/components/AlertMessage/AlertMessage.jsx`)
  - Displays validation and error messages
  - Handles success notifications

### Server Side

- **createUser** (`server/src/controllers/user.js`)
  - Input validation with `validateCreactUser()`
  - Email uniqueness check
  - Password hashing with bcrypt
  - JWT token generation
  - Database user creation

- **Rate Limiting** (`server/src/middleware/rateLimiter.js`)
  - 5 requests per 5 minutes window
  - Prevents brute force registration attacks

- **Authentication Middleware** (`server/src/middleware/authVerify.js`)
  - JWT token verification
  - User authentication for protected routes

## Security Features

- **Password Requirements**: Minimum 8 characters, uppercase, lowercase, numbers, symbols
- **Email Validation**: Format checking and uniqueness verification
- **Password Hashing**: bcrypt with 12 salt rounds
- **Rate Limiting**: Prevents automated registration attacks
- **JWT Tokens**: Secure authentication tokens with expiration
- **HttpOnly Cookies**: Prevents XSS token theft

## Error Handling

- **400 Bad Request**: Validation errors, duplicate email
- **500 Internal Server**: Database connection errors
- **503 Service Unavailable**: Database connection failure
