### Overview

When an authenticated user searches a string that is not cached as a whole, apifyScraperFetchPersister launches the Apify LinkedIn scraper in the background. Results are persisted for future searches while the current request returns immediately.

### Key Components

- **apifyScraperFetchPersister.js** (`server/src/services/apifyScraperFetchPersister.js`)
  - Owns the `inProgressScraperFetch` tracker and applies `cleanupInProgress()`
  - Starts scraping only when user is authenticated and the full string was not cached
  - Returns a user-facing message about new vacancies ETA

- **linkedInScraperFetch.js** (`server/src/services/linkedInScraperFetch.js`)
  - Interacts with the Apify API to run the LinkedIn jobs scraper actor.
  - Polls for completion and retrieves the dataset.
  - Normalizes results using `processScraperJob.js`.

- **processScraperJob.js** (`server/src/util/processScraperJob.js`)
  - Normalizes the specific data format returned by the Apify scraper to match the application's internal job schema.

### Background Nature

This process is **non-blocking** for the main job search request. The `JobController` does not `await` `apifyScraperFetchPersister`; it returns the current (cached or RapidAPI-fetched) results immediately. Scraper results appear in later searches after the background run finishes (typically within 1-10 minutes).
