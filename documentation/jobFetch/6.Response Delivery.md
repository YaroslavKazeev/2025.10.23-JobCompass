## Technical Implementation Details

### Server-Side Response Formatting

- **Shape**: `{ success: boolean, result: Job[], msg: string }`
- **Status codes**: `200` for success, `400` for invalid/missing `search_string`, `500` for DB or runtime errors.
- **Message source**: `msg` may include the Apify background scrape notice when triggered (via `apifyScraperFetchPersister`).

### Client-Side Response Processing

- `useFetch` sets `isLoading` true before the request and false after parsing.
- Success requires both `res.ok` and `jsonResult.success === true`; otherwise `error` is set to the backend `msg` or a fallback string.
- On success, `handleJobFetchResults` stores `allJobs`, saves any `msg` into `serverMessage`, and immediately triggers `fetchBatchTravelDetails`.
- Errors surface as `jobFetchError` in `JobsContext`; `OpenPositions` shows an `AlertMessage` and auto-clears after 5 seconds.

### User Experience Considerations

- **Loading**: `isJobsLoading` shows a full overlay; `isTravelLoading` shows a per-card spinner in `JobCard`.
- **Messaging**: `jobFetchError`, `travelFetchError`, or `serverMessage` render via `AlertMessage` with auto-dismiss.
- **Results Rendering**: Jobs are enriched with skills, filtered, sorted, and paginated; travel data is merged when available.
